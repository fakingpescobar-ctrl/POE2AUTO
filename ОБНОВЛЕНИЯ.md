### Self-healing vital offsets (`entity_reader.py:433-470`)

**Решение:**
```python
def _ensure_vital_offsets(self, life_addr: int):
    if self._vital_offsets_resolved:
        return

    # Проверяем текущий offset
    if self._vital_looks_valid(life_addr + self._health_off):
        self._vital_offsets_resolved = True
        return

    # Сканируем Life+0x80..0x400, ищем валидные VitalStruct
    found = []
    for scan_off in range(0x80, 0x401, 4):
        if self._vital_looks_valid(life_addr + scan_off):
            found.append(scan_off)
            if len(found) >= 4:
                break

    # Обновляем оффсеты
    self._health_off = found[0]
    self._mana_off = found[1]
    self._es_off = found[2]
```

```python
def _ptr(self, address: int) -> int:
    p = self._mem.read_pointer(address)
    if not p:
        return 0
    u = p & 0xFFFFFFFFFFFFFFFF
    if u < 0x10000 or u > 0x7FFFFFFFFFFF:  # user-mode x64
        return 0
    return p
```

**Новые методы в `mem_detect.py`:**

**`get_best_target()`** — лучшая цель для атаки:
```python
def get_best_target(self) -> Optional[EntityData]:
    hostiles = self.get_hostiles_in_range()
    if not hostiles:
        return None

    def target_score(e: EntityData) -> tuple:
        rarity_order = {
            Rarity.UNIQUE: 0, Rarity.RARE: 1,
            Rarity.MAGIC: 2, Rarity.NORMAL: 3,
        }
        is_boss_penalty = 0 if e.is_boss else 1
```

## 4. Auto offset discovery (0082628)

### Контекст

Оффсеты были захардкожены в `game_offsets.py`. При патче PoE2 (обновление 0.2.0) Health offset сместился с 0x1A8 на 0x1B0. Бот сломался.

### Три подхода

#### 4.1 АОБ-паттерны (`offset_discovery.py`)

**Новые паттерны:**

```python
EXTRA_AOB_PATTERNS = {
```

**Как работает AOB scan:**
1. Сканирует `.text` секцию .exe файла
2. Ищет уникальную последовательность байт
3. Читает RIP-relative displacement → вычисляет адрес глобального указателя
4. Дерференсит указатель → получает базовый адрес структуры

---

#### 4.2 Value-scan (`offset_discovery.py:180-220`)

**Идея:** Известно что HP игрока ≈ 5000. Сканируем Life компонент и ищем VitalStruct с Max=5000.

```python
def _value_scan_vitals(self, life_addr: int) -> bool:
    candidates = []
    for offset in range(0x80, 0x401, 4):
        data = self._mem.read_bytes(life_addr + offset, off.VitalStruct.SIZE)
        max_val = struct.unpack("<i", data[off.VitalStruct.MAX:...])[0]
        current = struct.unpack("<i", data[off.VitalStruct.CURRENT:...])[0]

        if not self._vital_looks_valid_at(max_val, current, reserved_flat):
            continue

        # Overlap detection
        is_dup = False
        for prev_off, prev_max, prev_cur in candidates:
            if abs(offset - prev_off) < off.VitalStruct.SIZE:
                if max_val == prev_max:
                    is_dup = True; break
                # Перекрытие: Max одного == Current другого
                if max_val == prev_cur or current == prev_max:
                    is_dup = True; break
        if is_dup:
            continue

        candidates.append((offset, max_val, current))
        if len(candidates) >= 3:
            break

    # Сортируем по Max (HP通常是最大的)
    candidates.sort(key=lambda x: x[1], reverse=True)
    self._health_off = candidates[0][0]  # Health
    self._mana_off = candidates[1][0]    # Mana
    self._es_off = candidates[2][0]      # ES
```

**Проблема с перекрытием:** При сканировании flat bytearray, чтение со сдвигом на 4 байта создаёт "ложные" VitalStruct (Max читается из Current предыдущей структуры). **Overlap detection** решает это: если Max кандидата == Current предыдущего — это перекрытие, не структура.

#### 4.3 Runtime валидация (`offset_discovery.py:120-160`)

```python
def validate(self, life_addr: int = 0) -> bool:
    now = time.perf_counter()
    if now - self._last_validate < self._validate_interval:  # 5 сек
        return True

    if self._vital_looks_valid(life_addr + self._health_off):
        self._consecutive_failures = 0
        return True

    # Оффсеты невалидны — re-scovery
    self._consecutive_failures += 1
    if self._consecutive_failures >= self._max_failures:  # 3
        self._value_scan_vitals(life_addr)
        return True
    return False
```

## 5. Transition dedup (7e3823a)

### Проблема

В PoE2 один портал может состоять из нескольких сущностей (visual portal + collision area + activation zone). При чтении `AwakeEntities` один и тот же переход появлялся 2-3 раза.

### Решение

```python
def get_transitions(self, dedup_radius: float = 0.5) -> List[EntityData]:
    transitions = [e for e in self._last_entities
                   if e.category == EntityCategory.TRANSITION]
    if not transitions:
        return []

    # Сортируем по расстоянию (ближайшие первые)
    transitions.sort(key=lambda e: e.distance)

    unique = []
    for t in transitions:
        is_dup = False
        for u in unique:
            dx = t.grid_x - u.grid_x
            dy = t.grid_y - u.grid_y
            if dx * dx + dy * dy <= dedup_radius * dedup_radius:
                is_dup = True
                break
        if not is_dup:
            unique.append(t)

    return unique
```

**Алгоритм:**
1. Фильтрует `EntityCategory.TRANSITION`
2. Сортирует по расстоянию от игрока
3. Для каждого перехода проверяет, есть ли уже уникальный в радиусе 0.5 клеток
4. Если нет — добавляет в список уникальных

**Тесты (9):**
- Пустой список
- Нет переходов
- Один переход
- Два далёких → оба остаются
- Два близких → один
- Три в двух кластерах → два
- Сортировка по расстоянию
- Кастомный radius

## 8. Известные проблемы

1. **Value-scan overlap** — при сканировании flat bytearray ложные positives возможны. Overlap detection помогает, но не на 100%.
2. **AOB-паттерны** — уникальны для конкретной версии .exe. При патче PoE2 могут сломаться.
3. **Entity persistence** — сущности не держатся между кадрами. Каждый `read_entities()` пересоздаёт список.
4. **Pathfinding** — не реализован. Бот держит R1, но не двигается к целям.
5. **MinimapIcon** — не читается. Нет иконок waypoints/encounters на радаре.
