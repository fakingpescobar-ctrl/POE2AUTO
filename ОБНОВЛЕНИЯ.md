### 2. POE2Radar интеграция (254f23a, 6b06329)

**Проблема:** Оффсеты были взяты из старого POE2GPS, после патча PoE2 сместились.

**Что сделали:**
- Синхронизировали оффсеты с POE2Radar (validated live 2026-06-04)
- VitalStruct layout: ReservedFlat@0x10, ReservedFraction@0x14, Regen@0x28, Max@0x2C, Current@0x30
- AreaInstance: LocalPlayer 0x5A0, AwakeEntities 0x6C0, TerrainMetadata 0x8A0
- Life: Health 0x1B0, Mana 0x208, EnergyShield 0x248

**Новые фичи:**
- `IsBoss` — MonsterComponent+0x27
- `WorldToScreen` — Camera+0x1A0, матрица 4x4
- `Terrain walkable` — nibble-packed grid

**Self-healing vital offsets:**
- Проблема: если GGG сдвигает оффсеты, бот ломается
- Решение: `_ensure_vital_offsets()` сканирует Life+0x80..0x400, ищет валидные VitalStruct
- Работает автоматически при первом обращении

**Recycle guard:**
- Проблема: адреса сущностей переиспользуются в пределах зоны, кэш показывает старые данные
- Решение: `_id_cache` — если entity_addr уже был с другим id, эвиктим кэш

**Safe ptr validation:**
- Проблема: `_ptr()` читал мусорные адреса
- Решение: отсекаем адреса вне `0x10000..0x7FFFFFFFFFFF` (user-mode x64)

**Single-read std::map node:**
- Проблема: 5 отдельных чтений для одного узла дерева
- Решение: одно чтение 48 байт,.unpack вручную

### 3. Memory-first mob detection (4333a03)

**Решение:** Прямое чтение памяти через PROCESS_VM_READ.

**Новые методы:**

- `get_lowest_hp_target()` — для добивания

**Auto-flask система:**
- `AutoFlaskEngine` + `FlaskRule` — правила: hp_below, mana_below, enemies_nearby
- 4 дефолт правила в `config.yaml`

**Research tools (`research.py`):**

- `--entity <addr>` — дамп компонентов

- `--dump <addr> <size>` — hex dump

### 4. Auto offset discovery (0082628)

**Проблема:** Оффсеты были захардкожены. При патче PoE2 ломались.

**Три подхода:**

#### 4.1 АОБ-паттерны
- GameStates: `cmp [rip+rel32], rbp` (был)
- Camera: новый паттерн
- LocalPlayer: новый паттерн

#### 4.2 Value-scan
- Сканирует Life+0x80..0x400, ищет валидные VitalStruct
- Сортирует по Max (HP通常是最大的)
- Overlap detection: если Max кандидата == Current предыдущего → это перекрытие, не структура

#### 4.3 Runtime валидация
- Каждые 5 сек проверяет текущие оффсеты
- После 3 неудач → auto-recovery (re-scan)
- При смене зоны → принудительный re-scan

**Интеграция:**
- `entity_reader.py`: `initialize_discovery()`, `validate_offsets()`, `force_rescan()`
- `mem_detect.py`: discovery init при подключении, validation в `update()`, re-scan при смене зоны
- `research.py`: команды `--discover`, `--validate`, `--rescan`

**Тесты:** 28 новых для `offset_discovery.py`.

### 5. Transition dedup (7e3823a)

**Проблема:** Один и тот же переход (portal/doorway) появлялся несколько раз в списке сущностей.

- Группирует переходы по позиции (euclidean distance ≤ radius)
- Оставляет ближайший к игроку в каждой группе
- Сортирует по расстоянию

## Известные проблемы

- **Offset discovery** — value-scan может находить ложные VitalStruct из-за перекрытия байт в памяти. Overlap detection частично решает, но не на 100%.
- **AOB-паттерны** — уникальны для конкретной версии PoE2. При патче могут сломаться.
- **Entity persistence** — сущности (transitions/NPCs/chests) не держатся между кадрами. При каждом `read_entities()` список пересоздаётся.
- **Pathfinding** — не реализован. Бот держит R1, но не двигается к целям.
